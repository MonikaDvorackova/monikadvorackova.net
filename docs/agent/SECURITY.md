# Agent platform security review

Reviewed boundaries: public-content ingestion, REST request/response validation, MCP read-only tools, A2A task ownership, PostgreSQL transactions, audit integrity, inquiry retention, GitHub public-source filtering, embedding-provider failure and disabled notifications.

- No public data-modification endpoint exists. Storing inquiries requires a dedicated key, schema validation, consent and an idempotency key. Notification approval requires the separate admin key; delivery additionally requires an explicit activation record and provider configuration. No outbound worker has been enabled or run.
- A2A task operations are authenticated and credential-scoped. Per-task/message advisory locks serialize replay, status and cancellation. Terminal tasks cannot restart. Task history has a seven-day retention period. Requests cannot invoke external actions.
- The database ledger serializes append operations and rejects UPDATE/DELETE with an immutable trigger. Chain verification detects modified/reordered records. An independently retained head is necessary to detect whole-chain replacement or suffix truncation by a privileged database owner. Runtime credentials must not own schema/migration privileges.
- Discovery and query responses use only public MDX, curated bibliography/stack, source-reviewed career records and whitelisted GitHub fields. Private repository results and repository names associated with credential/reset/backup/incident handling are excluded. GitHub PR states are structured separately from verification status and upstream/own-repository scope.
- No user-supplied URL is fetched. GitHub and embedding requests use fixed upstream origins with bounded timeouts and redirect rejection. Source revalidation uses fixed HTTPS host allowlists and does not follow redirects. The notification adapter targets only the fixed provider API and configured operator recipient.
- Extractive QA never evaluates retrieved text or gives it tool access. It filters instruction-like source descriptions and retains citation status. This is evidence retrieval, not proof of entailment: questions outside supported material must abstain. Semantic provider credentials are never returned to clients.
- Request bodies are capped at 16 KiB during streaming. Unknown payload fields are rejected. Errors are sanitized. Browser CORS/origin policy is restricted. Edge infrastructure must replace forwarded client-address headers; durable rate limits and a dedicated HMAC salt are production requirements.
- Security headers add nosniff, frame denial, restrictive permissions and a referrer policy. TLS/HSTS are hosting responsibilities. An enforced CSP has not been introduced without browser compatibility validation for the existing visual site and analytics.

These are recorded as residual dependency risk, not silently suppressed. Live embedding retrieval, mail delivery, preview PostgreSQL activation and production edge configuration remain unverified.
